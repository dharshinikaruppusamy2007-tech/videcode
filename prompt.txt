### Fixed backend contract (do not deviate)

```
POST /api/interview

// Turn 1 (start session)
{ "sessionId": "abc-123", "candidate": { ...candidate object... } }
-> { "reply": "...", "done": false }

// Turn 2+ (continue session)
{ "sessionId": "abc-123", "message": "..." }
-> { "reply": "...", "done": false }

// Final turn
-> {
     "reply": "Interview completed.",
     "done": true,
     "feedback": {
       "summary": "...",
       "strengths": ["..."],
       "gaps": ["..."],
       "next": ["..."]
     }
   }
```
No auth. In-memory session store keyed by `sessionId` is fine. Minimum: 8
questions across at least 4 curriculum days, follow-ups based on prior
answers, structured feedback at the end.

I'll provide `curriculum.json` (31 days: title, objectives, tools per day) and
`candidates.json` (per-candidate mission results: passed/skipped/attempts)
as data files.

### STEP 4 — API endpoints
Implement in `/routes`:
- `GET /api/candidates` → returns the 3 demo candidates (id, name, role) for
  the login screen's candidate list
- `GET /api/candidates/:id/dashboard` → returns candidate name, completed
  days, skipped days, modules completed/total, overall progress %, completed
  topics list, skipped topics list (for the Dashboard screen)
- `POST /api/interview` → exactly the contract above:
  - New session (has `candidate`, no prior state) → build plan, call Gemini
    for opening turn, store session, return `{reply, done:false}`
  - Continue session (has `message`) → append to history, call Gemini,
    **server-side gate**: only honor `done:true` from Gemini if
    `turnCount >= 8` and `daysCovered >= 4`, otherwise ignore and continue
  - On honored end → call `getFeedback`, return final response with
    `feedback` (including `overallScore`/`breakdown`), clear session
- In-memory `Map` session store, no persistence/auth needed
